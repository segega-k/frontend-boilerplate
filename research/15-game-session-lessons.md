# 15. Уроки сессии разработки игры «Шахтёр» (dadya-shakhter)

Status: done
Updated: 2026-10-15
Источник: транскрипт Claude-сессии `90cdc3ec-9706-420a-a0ed-f36696707488` (проект `C:/Работа/Shakhter/dadya-shakhter`,
Telegram Mini App «Gift Miner»: мины 5×5, «Мегаящик» с лентой-рулеткой, кейсы, Lottie-сцена шахты) и память этого
проекта. Прочитал оркестратор целиком.

## Summary

1. **Главный технический вывод: для этих игр canvas-движок не нужен, нужен быстрый Lottie-конвейер.** Сцена — это
   DOM-интерфейс плюс набор Lottie-слоёв (шахтёр, кристаллы, взрыв, спуск). Тормозила именно отрисовка Lottie на
   iPhone 16 Pro Max, «невозможно сильно».
2. **Что реально ускорило (по замерам):** холст каждого слоя размером со свой рисунок (10.55 → 0.75 МП); замена
   track matte-масок на обрезку (99 масок, 26 МП копирований за кадр → 0); рисовать с частотой анимации, а не экрана
   120 Гц; dotLottie (ThorVG/WASM) **только в Web Worker через OffscreenCanvas** (в основном потоке dotLottie был в 4–6
   раз медленнее lottie-web); тяжёлые заставки — заранее отрендеренное H.264-видео (спуск 77/120 мс → 16.7/20 мс на
   кадр); предзагрузка и сборка плееров в простое на лобби; адаптивная плотность пикселей 1.5 → 1.
3. **Эмуляция лгала.** В Edge было 60 fps, на iPhone лагало. Причины увидели только через диагностическую панель на
   устройстве (`?perf=1` / `startapp=perf`, отчёт копируется текстом): iOS отказывал `play()` видео вне жеста (Low
   Power Mode), и спуск молча уходил на медленный путь.
4. **iOS-правила:** `play()` видео только внутри обработчика нажатия; Low Power Mode режет autoplay и, вероятно,
   ограничивает 30 fps; OffscreenCanvas с iOS 16.4; View Transitions API нет в iOS < 18 и старых вебвью.
5. **CSP молча выключает ускорения:** без `worker-src 'self' blob:` нет воркеров, без `media-src 'self' blob:` нет
   видео, для WASM нужен `wasm-unsafe-eval`. Всё откатывалось на медленный путь без ошибки на экране.
6. **Мерить только продакшен-сборку.** Dev-сервер через туннель отдавал 268 запросов и 4.9 МБ вместо 0.6 МБ на спуск
   без сжатия. Preproduction долго стоял на старом образе, и «всё ещё лагает» было про старую сборку.
7. **Процессные инциденты агентов:** пушили без просьбы (3 раза); сломали общий `node_modules` через временный
   worktree со ссылками на него и `git worktree remove --force`; делали `git stash` на общей рабочей копии, где лежала
   незаконченная работа других агентов; агент сам нарисовал ассет (взорванная бочка) — правильно пометил и сообщил.

## Findings

### A. Lottie-конвейер для игровых сцен

| Проблема | Решение | Эффект (эмуляция, CPU ×4) |
| --- | --- | --- |
| каждый Lottie-слой на полноэкранном холсте 1440×2560 | холст по bbox рисунка слоя | площадь холстов 10.55 → 0.75 МП |
| 99 track matte-масок, каждая через 2 доп. холста | при загрузке JSON маски переписываются в clip-path | 26 МП копирований за кадр → 0; покой 9 → 60 fps в софт-рендере |
| отрисовка на каждый кадр экрана 90–120 Гц | рисовать только собственные кадры анимации (60) | основной поток 923 → 420 мс/с |
| сборка плеера броска в момент нажатия (+170–300 мс) | плееры собираются заранее, как только выбран кристалл | нет задержки на тапе |
| dotLottie в основном потоке (уже был в main) | `DotLottieWorker`, 3 воркера: спуск, персонаж, окружение | кадр основного потока 77 → 3.3 мс |
| спуск: 223 слоя, 820 заливок и 560 обводок на кадр | пререндер в H.264 MP4 (`pnpm run images:lottie-video`, ffmpeg), Lottie как запасной путь | 16.7 мс/кадр, 60 fps |
| первый вход: сборка плеера 0.7 с, монтаж сцены | в простое на лобби (`requestIdleCallback`) разбор JSON, сборка плееров, декод картинок; видео качается сразу после старта приложения; если не успело, играет потоком | худший кадр 997 → 233 мс; тап → первый кадр 575 → 187 мс |
| слабые устройства | DPR 1.5, падение до 1, если < 45 кадров в первую секунду; без предзагрузки при Save-Data/2G; при памяти < 4 ГБ только разбор | — |

Требования к Lottie-ассетам от дизайнера (выявлены анализом файлов): веб-плееры не поддерживают expressions (28 в
`intro.json`) и часть эффектов (30 glow/blur) — их нужно запекать; merge paths игнорируются; маски дорогие; 12 файлов
персонажа по ~500 КБ дублируют одну риггинг-структуру. Нужен чек-лист экспорта и бюджет на файл.

Переходы между Lottie-клипами персонажа: клипы стартуют не с 0, а с кадра, совпадающего с текущей позой (`enterAt`);
до ответа сервера замах держится на кадре развилки (`holdAt`), промах и попадание подхватывают с него; смена ассета
(целая бочка → взорванная) делается в кадре, полностью закрытом огнём. Crossfade не подошёл: двоились тонкие детали.
Результат раунда всегда от сервера, анимация «садится» на него.

### B. Лента-рулетка «Мегаящика»

Разгон ~190 мс (не старт на полной скорости), ровное торможение, перелёт ~22 px с возвратом за ~400 мс, вспышка
выигрыша 0.36 с и отскок метки, 3–5 лёгких вибраций Telegram на последних плитках не чаще раза в 120 мс; только
`transform`; motion blur отвергнут (лента ~6300 px, дорого на Android); длительность прежняя; выигрыш решает сервер;
reduced-motion — сразу на выигрыш.

### C. Интерфейс игры (DOM)

- `ModalPresence`: держит закрытое окно в дереве, пока идёт анимация ухода; затемнение 240 мс, лист снизу 320 мс,
  закрытие ~200 мс; во время ухода нет нажатий; фокус возвращается к открывшей кнопке. Все шторки, включая окно ставки,
  на одном механизме.
- Страница, центрированная через `transform`, ломает fixed-оверлеи и фокус-скролл («модалка падает с потолка») →
  `overflow: clip` вместо `hidden`, модалки выносить порталом за трансформированный контейнер.
- Переход между экранами: только fade 240 мс; сдвиг запрещён тестами «ничто не сдвигается > 0.5 px»; View Transitions
  отклонён (iOS < 18, блок нажатий, скролл).
- Ховер: `brightness(0.92)` и `scale: 0.995` (свойство `scale`, не `transform`), только `(hover: hover) and
  (pointer: fine)`, `cursor: pointer`/`default`; у кнопок-иконок значок до 72 % непрозрачности. Пользователь трижды
  уменьшал масштаб: 0.98 → 0.99 → 0.995 («почти незаметно, чуть ли не крайность»).
- Копирование: Clipboard API с запасным `execCommand`, иконка → галочка на 1.8 с, вибрация, объявление «Скопировано».
- Горизонтальные вкладки: свайп не утягивает шторку и не закрывает Telegram, колесо мыши листает вбок, выбранная
  вкладка докручивается.
- Широкий экран: колонка ~437 px по центру, фон по бокам совпадает с фоном экрана (без тени на колонке); для игровой
  сцены «крылья» — зеркальный фон сцены с лёгким blur 3 px и затемнением к краям, только ≥ 480 px; во время загрузки
  крылья без персонажей.
- Telegram: нижний inset поднимает **всю** сцену (кристаллы, области нажатия, анимации), а не только кнопки; фон
  сцены продолжается под полосу жестов; fullscreen только на мобильных (на ПК режим задаётся и в BotFather); в Telegram
  Web cookie `SameSite=lax` ломают вход.
- Повторная «ИИ-шность»: виджет «не хватает звёзд» был красным баннером ошибки с лососевым цветом не из палитры и
  текстом 11 px. Переделан в компактную пилюлю из существующих частей (форма пилюли баланса, звезда со «Ставки»,
  синий «+»), без тени и свечения; настоящие ошибки остались баннером.

### D. Инфраструктура разработки TMA

- Демо/preview-режим на `localhost` (раунды считаются в браузере, без API и входа) позволяет делать UI без Telegram;
  для туннеля нужно добавлять хост туннеля в `allowedHosts` Vite и в правило демо-режима.
- Туннели: cloudflared (trycloudflare), ngrok (нужен токен), tuna (бесплатно ~30 мин на сессию, адрес меняется). Для
  проверки на телефоне туннель ставить на **продакшен-сборку** (`vite preview` / nginx), не на dev-сервер.
- HMR через туннель требует отдельной настройки wss и ломает localhost — не делать по умолчанию.
- Claude Code останавливает фоновые процессы при нехватке памяти; tuna и dev-сервер падали по лимитам.
- E2e только на собранном бандле; эталонные скриншоты на 390/437; известные падения фиксировать списком, чтобы не
  путать с новыми.

### E. Процесс и агенты

- В том проекте пользователь велел главному агенту быть **только оркестратором**: все задачи параллельным агентам.
- Параллельные агенты в одной рабочей копии: договорились, что каждый дописывает свой блок в конец общего CSS. Это
  работало, но typecheck/lint общей копии краснели от чужой незаконченной работы, а сборка для проверки на телефоне
  захватывала незаконченные правки.
- Инциденты: push без просьбы (агенты, 3 раза); поломка `node_modules` через временный worktree со ссылками на общие
  зависимости и `git worktree remove --force`; `git stash` на общей копии. После этого в промпты агентов добавлялось
  жёсткое правило «никаких временных копий со ссылками на node_modules, никаких stash и удаления зависимостей».
- Коммиты от идентичности пользователя в этом репо (`segega-k`), а не той, что в `AGENTS.md`; переписывание истории
  после пуша дало non-fast-forward.
- Агент, сделавший ассет вместо дизайнера, пометил файл и вынес на показ дизайнеру — правильное поведение.
- «Всё летает» пользователь подтвердил только после видео-спуска + запуска `play()` в тапе + воркеров.

## Recommendations for the boilerplate

**Шаблон `game` (пересмотр 05e, передано агенту 14):**
1. Базовый стек для крутилок, колёс, рулеток, карт: DOM/CSS + React для интерфейса, Lottie для персонажей и эффектов,
   CSS/WAAPI-анимации на `transform`/`opacity` для лент и колёс. Canvas-движок (Phaser/Pixi) — опция, не дефолт.
2. Пакет `packages/lottie-runtime` (или внутри game): dotLottie в Web Worker (OffscreenCanvas) с автоматическим
   откатом в основной поток; кадрирование холста по bbox; переписывание track matte в clip; рисование с частотой
   анимации; лимит DPR 1.5 с адаптацией; API переходов по позам (`enterAt`, `holdAt`, `onPlayhead`); предзагрузка и
   пред-сборка в простое; пул плееров.
3. Конвейер пререндера тяжёлых Lottie в видео (скрипт + ffmpeg), H.264 для непрозрачных, проверка альфы для
   прозрачных; запуск `play()` в обработчике тапа; поток, если не докачалось; Lottie как запасной путь.
4. Диагностическая панель производительности (`?perf=1` / `startapp=perf`) — стандартная часть шаблонов `tma` и
   `game`: путь отрисовки и причина отката, тайминги, fps, пропуски видео, CSP-ошибки, устройство, build hash.
5. CSP-профиль игры в `security-headers.conf`: `worker-src 'self' blob:`, `media-src 'self' blob:`,
   `wasm-unsafe-eval`; e2e-тест, что воркеры и видео не откатываются молча.
6. Чек-лист Lottie-ассетов для дизайнера: без expressions, эффекты запечены, минимум масок, без merge paths,
   общий риг, бюджет КБ на файл, dotLottie-упаковка; скрипт-анализатор файлов (слои, маски, заливки на кадр).
7. Рецепты в `apps/game/CLAUDE.md`: лента-рулетка (кривая, перелёт, вибрации), колесо фортуны, карты (раздача,
   переворот, drag), результат только с сервера, reduced-motion.
8. Широкий экран для TMA/игры: колонка + фон-продолжение, крылья сцены — готовый компонент.

**Общие для всех шаблонов:**
9. `ModalPresence` (exit-анимации, фокус, блок нажатий при уходе) — в kit; запрет `overflow: hidden` на
   трансформированных страницах (`clip`), модалки через портал.
10. Ховер-токены по умолчанию: `brightness(0.92)`, `scale 0.995`, только `(hover:hover) and (pointer:fine)`;
    иконки — opacity. Это совпадает с анти-слоп правилом «hover без подъёма».
11. TMA: нижний inset сдвигает весь контент; демо/preview-режим без Telegram; `pnpm tunnel` к продакшен-сборке с
    авто-`allowedHosts`; fullscreen только на мобильных.
12. Проверка производительности и e2e только на продакшен-сборке; `/version.json` и build hash видны в диагностике,
    чтобы не путать старый образ preproduction с новым.

**AI-слой и процесс:**
13. Guard-хук обязан блокировать `git push` без явной просьбы — агенты пушили, хотя им запрещали текстом.
14. Правило для параллельных агентов: каждый в своём git worktree со своим `pnpm install` (не ссылками на общий
    `node_modules`); запрет `git stash`/`reset` на общей копии; запрет `git worktree remove --force`; сборка для
    проверки — только из закоммиченного состояния.
15. Режим «оркестратор» как поддерживаемый сценарий: skill/инструкция для главного агента (раздать, собрать, проверить
    коммит на чужие правки), с правилами моделей из `.claude/agents`.
16. Идентичность коммитов берётся из git config пользователя; агент не переопределяет её и не пишет трейлеры.
17. Ассеты, сделанные агентом, помечаются и выносятся на подтверждение дизайнеру.
