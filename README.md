# frontend-boilerplate

AI-based фронтенд-бойлерплейт для быстрого старта проектов. Собран на основе опыта прошлых проектов и заточен под работу с Claude Code.

> **Статус:** v0.1 — концепция. Конкретные пресеты и технологии в них ещё обсуждаются (см. [Открытые вопросы](#открытые-вопросы)).

---

## Ключевые идеи

### 1. Единая конфигурация Claude Code

Правила, скиллы, настройки и подключённые MCP-серверы хранятся **в репозитории**, а не локально на машине. Поэтому любая сессия Claude на любом устройстве получает одинаковое окружение сразу после `git clone`.

Что входит:

- `CLAUDE.md` — главный файл контекста проекта (точка входа для Claude);
- `.claude/settings.json` — общие настройки (сейчас: стиль ответов `Human`);
- `.claude/output-styles/Human.md` — стиль ответов: итог первой фразой, без пересказа процесса;
- `.claude/skills/` — скиллы (сейчас: `frontend-design` против шаблонного «ИИ-шного» дизайна);
- `.claude/agents/`, `.claude/commands/` — по мере появления;
- `.mcp.json` — список MCP-серверов проекта (планируется).

Личные/машинные переопределения — в `.claude/settings.local.json` и `CLAUDE.local.md` (в `.gitignore`).

### 2. Полный контекст по правилам кода

Правила собраны из прошлых проектов (xRocket, Awaaz-e-Sehat): из CLAUDE.md, docs и памяти Claude, а также из поправок,
которые давались по ходу работы. Почти у каждого правила указана причина, а у правил, родившихся из поправки, приведена
исходная цитата. AI-документы написаны на английском, как и в прошлых проектах.

| Файл                                             | О чём                                                                 |
| ------------------------------------------------ | --------------------------------------------------------------------- |
| [CLAUDE.md](CLAUDE.md)                           | точка входа: карта документов, главные правила, чек-лист после задачи |
| [docs/workflow.md](docs/workflow.md)             | как работать: объём задачи, план и одобрение, агенты, баги, моки, git, отчёты |
| [docs/architecture.md](docs/architecture.md)     | домены и слои, правила импортов, view / view model / store, данные, ошибки, навигация, i18n, SSR |
| [docs/code-style.md](docs/code-style.md)         | файлы, комментарии, TypeScript, логика, импорты, кроссплатформенность, тесты |
| [docs/naming.md](docs/naming.md)                 | имена файлов, флагов, обработчиков, сущностей                         |
| [docs/components.md](docs/components.md)         | API компонентов: строки и слоты, без лишних флагов, состояния, Storybook, замена компонентов |
| [docs/design.md](docs/design.md)                 | макет как источник правды, токены и темы, иконки, движение, состояния, адаптив, анти-ИИ-дизайн |

| [docs/library-notes.md](docs/library-notes.md)   | подводные камни конкретных библиотек: Tamagui, RNW, MobX, TanStack, Vike, Telegram… |

### 3. Инициализация одним скриптом

При первом запуске проект настраивается **одной командой**. Скрипт в интерактивном режиме (в терминале) спрашивает, какой тип проекта нужен, и **удаляет весь код, конфиги, зависимости и правила, не относящиеся к выбранному варианту**.

Пример: выбран «Лендинг» → всё, что нужно только для магазина и ТМА, удаляется.

Предварительный список пресетов:

| Пресет   | Описание                     |
| -------- | ---------------------------- |
| Лендинг  | Промо-/маркетинговый сайт    |
| Магазин  | Интернет-магазин             |
| ТМА      | Telegram Mini App            |

Требования к скрипту:

- **один скрипт = полный результат**, без ручных доработок после;
- кроссплатформенность (Windows / macOS / Linux);
- чистит не только код, но и зависимости в `package.json`, конфиги, правила и скиллы Claude, разделы документации;
- после выполнения проект собирается и запускается без ошибок;
- одноразовый: после инициализации сам скрипт и вспомогательные файлы тоже удаляются.

### 4. Единая инфраструктура

Одинаковое окружение разработки и развёртывания на любом устройстве:

- зафиксированные версии Node.js и пакетного менеджера;
- единые линтеры, форматтеры, git-хуки;
- общие переменные окружения через `.env.example`;
- единые скрипты для запуска, сборки и деплоя.

## Быстрый старт

> Команды будут уточнены после выбора стека.

```bash
git clone <repo-url> my-project
cd my-project
<install>        # установка зависимостей
<init>           # интерактивный выбор пресета и очистка лишнего
<dev>            # запуск dev-сервера
```

---

## Предполагаемая структура

```
.
├── .claude/
│   ├── settings.json     # общие настройки Claude Code
│   ├── output-styles/    # стиль ответов Human
│   ├── skills/           # скиллы
│   └── agents/           # сабагенты
├── .mcp.json             # MCP-серверы проекта
├── .gitattributes        # LF во всех файлах на любой машине
├── CLAUDE.md             # главный контекст для Claude
├── docs/                 # правила кода, архитектуры, дизайна, тулинга
├── scripts/
│   └── init/             # скрипт первичной инициализации
├── src/                  # исходный код (общий + код пресетов)
└── README.md
```
